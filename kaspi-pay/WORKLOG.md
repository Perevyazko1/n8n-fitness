# kaspi-pay — WORKLOG

Учёт трат по карте Kaspi Gold (Вьетнам и не только): PDF-выписка из Kaspi → Kaspi-бот в Telegram →
n8n разбирает и пишет в Postgres → ответ в бот, итоги в ₸ и ₽ по курсу ЦБ.

## Что есть на сервере (проверено 2026-11-07)

- n8n 2.18.5, Public API включён (401 без ключа). Ключа у Claude нет, импорт JSON делает пользователь.
- Postgres 16 (`fitness-db`), credential в n8n — `PG`.
- Credentials: `Kaspi Bot` (Telegram, id `SaBX5QH2O5ySg31H`), `Kaspi X-Token` (Header Auth,
  id `IDIC0lbFVsScUBX9di` — нужен был только для скриншотов, сейчас не используется).
- RAM 2 ГБ, свободно около 950 МБ.

## Что где лежит

- `sql/schema.sql` — `kaspi_expenses` (все строки выписки, суммы со знаком, дедуп `dedup_key` UNIQUE)
  + `kaspi_fx_rates` (кэш курса ЦБ по дню).
- `Kaspi_Statement_Bot.json` — Telegram Trigger бота → только владелец (chat_id в `Config`, 648226895)
  → PDF? → скачать → Extract From File (pdf) → разбор кодом → курс ЦБ → INSERT ON CONFLICT → ответ.
  Не PDF — подсказка, как выгрузить выписку.
- Mini App — в общем Django (`backend/`), не здесь: страница `backend/fitness/templates/kaspi/app.html`
  (отдаётся на `https://n8n-fitness.ru/api/kaspi/app`, открыта), данные — `POST /api/kaspi/summary`
  `{initData, period: day|week|month}`, код `backend/fitness/kaspi.py`. initData проверяется токеном
  Kaspi-бота (`KASPI_BOT_TOKEN`), пускаются `KASPI_ALLOWED_IDS` (через запятую, траты общие на двоих); ветка в `fitness/middleware.py`.
  Отдельный репо под GitHub Pages не заводили: тот же origin, без CORS.
- `archive/Kaspi_Expense_Ingest.json` — первый вариант: скриншот через «Команды» iOS + LLM. Похоронен:
  Kaspi запрещает скриншоты («снимок экрана недоступен в целях безопасности»).

## Решения и грабли

- Разбор без LLM: текст склеивается в одну строку и режется по «ДД.ММ.ГГ ± сумма ₸ Операция»,
  поэтому от переносов строк не зависит. Сверка: сумма покупок + курсовой разницы обязана совпасть
  со строкой «Покупки» из сводки выписки, иначе в ответе предупреждение. На выписке 01–08.11.26:
  28 операций, сверка до копейки.
- Пишем все операции; в траты идут только `kind IN ('purchase','fx_diff')`. Переводы людям, пополнения,
  снятия — записаны, но в итоги не входят (решение пользователя 2026-11-08).
- «Курсовая разница» — отдельная строка выписки по уже проведённой покупке (`fx_diff`). Возвраты
  (GRAB +18,24 / −18,24) гасятся сами: суммы со знаком.
- Времени в выписке нет. Одинаковые траты в один день (2× YANDEX.GO по 890) различаем порядковым
  номером `occ` внутри дня: ключ `дата|сумма|kind|продавец|N`. Повторная/пересекающаяся выписка
  дописывает только новое.
- Риск: если заблокированная сумма (значок часов, «ожидает подтверждения») при проведении изменится
  в самой строке — получим дубль. По наблюдению Kaspi оставляет сумму и добавляет «Курсовую разницу»,
  но проверить на следующей выписке.
- Даты, скорее всего, по времени Казахстана (UTC+5), а не Вьетнама (UTC+7).
- Рубли считаются по последнему кэшированному курсу ЦБ на момент загрузки, не на дату операции.
- В выписке ИИН, номер счёта и остаток — сырой текст в БД не храним.
