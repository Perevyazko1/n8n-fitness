### 4. Грабли, на которые уже наступили

- **n8n: привязать credential к httpRequest — мало.** Без полей
  `"authentication": "genericCredentialType"` + `"genericAuthType": "httpHeaderAuth"`
  нода шлёт запрос БЕЗ заголовка и ловит `401`, а с `continueRegularOutput` это выглядит
  как «прогон успешен, но данных нет». При сборке воркфлоу JSON-ом проверять первым делом.
- **Travelpayouts отвечает ГОРОДСКИМИ кодами, не аэропортовыми.** Спрашиваешь `CXR` —
  приходит `NHA`, `GYD` → `BAK`, на `DXB` вдобавок сыплется `SHJ` (Шарджа). Фильтр по
  from/to сравнивал с запрошенным кодом → Нячанг выпадал целиком. В списках держать то,
  что API ОТДАЁТ.
- **`/v1/prices/calendar` для архива не годится** — отдаёт цены ТУДА-ОБРАТНО (100 % записей
  с `return_at`, 45–64 тыс. против one-way 12–22 тыс.) и игнорирует запрошенный месяц,
  растягиваясь на год вперёд. Завышал медиану на ~60 %. Выкинут.
- **`/v2/prices/latest` — годный архив.** `data` = массив
  `{origin, destination, depart_date, value, number_of_changes, duration, gate, found_at, return_date}`;
  при `one_way=true` все `return_date` пустые.
  Параметры: `period_type=year&beginning_of_period=YYYY-01-01&group_by=dates&show_to_affiliates=false&sorting=price&limit=1000`.
  **Ограничение:** с `group_by=dates` это одна цена НА КАЖДУЮ ДАТУ, то есть медиана = «типичная
  дата окна», а НЕ исторический уровень. Ответить «дешевле ли, чем неделю назад» чужой архив
  не может — для этого нужен свой снапшот в Postgres (сознательно не заводили).
- **Запуск руками:** общий Execute Workflow вешается на ожидании telegram-триггера, ноды не идут.
  `Execute step` на триггере гоняет только его. Правильно — `Execute step` на `Aggregate`:
  выполнит всё выше и не тронет Telegram. CLI `n8n execute` не работает: требует
  Execute Workflow Trigger, которого в воркфлоу нет.

### 2. Новые источники

**AirHint** — вердикт «брать или ждать», открытый JSON без токена и кук:

```
GET https://www.airhint.com/predict/{airline}/{origin}/{dst}/{YYYY-MM-DD}?price=&currency=RUB&passengers=1
→ {"suggestion":"Buy|Wait","confidence":5,"price_range":[26392,62117,37431],"max_saving":null}
```
- `price` обязан быть в валюте `currency` — с USD и рублёвой ценой вердикт переворачивается.
- Код авиакомпании игнорируется (`XX` == `VJ`, ответ байт-в-байт), коды нормализуются (`CXR` == `NHA`).
- `price_range` **не зависит от даты** — это вилка по МАРШРУТУ, так и подписываем. Часто `null`.
- Ответы только по-английски, `locale=ru` не работает. Шкала `confidence` неизвестна.
- Дёргается **только на выходе**: нода между `Prepare` и `Telegram Alert` (то есть вместе
  с алертом, единицы раз в сутки) и ≤6 запросов в `/prices`.

**tutu — настоящий поиск** `offers-api` (тело запроса снято playwright'ом, работает обычным curl):

```
POST https://offers-api.tutu.ru/avia/offers/v2      Content-Type: text/plain;charset=UTF-8
Referer: https://avia.tutu.ru/ + браузерный UA
{"passengers":{"child":0,"infant":0,"full":1},"serviceClass":"Y",
 "routes":[{"departureCityId":112,"arrivalCityId":117,"departureDate":"2026-10-20"}],
 "searchId":"<uuid>","sessionId":"<uuid>","pageId":"любой","userData":{},"source":"offers",
 "dynamicFilters":{"optionFilters":[],"rangeFilters":[],"buttonFilters":[],"shortcuts":[],"switchFilters":[]},
 "offset":0,"isNewSearch":true}
```
- uuid произвольные, не проверяются. Ответ gzip — нужен `--compressed`, и это массив из ОДНОГО объекта.
- Цена: `offers.actual[id].offerVariants[].price.value` = `{amount, fraction}` → **amount / fraction**.
  Времена и перевозчики — `dictionary.common.segments` / `.carriers`, IATA — `dictionary.avia.points`.
- **Календарь и поиск — разные данные.** Календарь по SCO/ALA/NQZ обрывается на начале октября
  и параметрами не двигается, а поиск октябрь отдаёт нормально. Календарём проверять покрытие нельзя.

### 3. Живой мониторинг — ответ на протухший кэш

Повод: у Travelpayouts поймали цену, **устаревшую на 21 час**. Кэш на это неспособен
в принципе, поэтому от того же крона идёт вторая ветка
`Live Queries → Tutu Live → Live Check → Telegram Live`.

- Обходит слоты «маршрут × дата» **по кругу** (курсор в staticData), 6 слотов за прогон.
  Маршруты: ALA→HAN, NQZ→HAN, ALA→DAD, ALA→NHA, NQZ→DAD, NQZ→NHA × 16 дат = 96 слотов,
  полный круг ~80 минут, ~72 запроса в час к tutu.
- Пинг при падении ≥ 7 % или при цене ≤ 30 000 ₽ ниже прошлой. **Первый замер только
  запоминается** — иначе при первом запуске улетело бы 96 сообщений.
- Текст заканчивается «беги проверять на Aviasales и у перевозчика»: это индикатор движения
  цены, а не цена покупки — у tutu агентская наценка.
- `/prices` показывает живую доску из staticData **бесплатно**, без единого запроса.

Плюс при каждом алерте один живой запрос по **подвозу** SCO→ALA/NQZ на дату алерта:
расхождение с кэшем печатается прямо в сообщении («дешевле кэша на N ₽» / «цена могла протухнуть»).
